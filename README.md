# CompactCodes

## Overview

CompactCodes is a small .NET library that generates compact, URL-path-safe random codes. It supports referral, campaign, invitation, and similar opaque identifiers.

It generates and validates codes only. It does not store them, resolve redirects, check uniqueness, retry database collisions, or authorize access.

## Install

The library targets .NET 8 and .NET 10. The repository currently produces a local NuGet package named `CompactCodes` at version `1.0.0`. Only the local package is verified; availability on public NuGet feeds has not been checked.

To reference the source project from another project:

```xml
<ProjectReference Include="..\CompactCodes\src\CompactCodes\CompactCodes.csproj" />
```

To consume the package built locally in this repository, point NuGet at the local package directory:

```powershell
dotnet add YourApp.csproj package CompactCodes --version 1.0.0 --source ..\CompactCodes\artifacts\packages
```

The DI quick start below uses `Microsoft.Extensions.DependencyInjection`. Standalone console applications should reference that package (the sample uses version `9.0.0`); hosted applications can use their existing DI container.

## Quick start

Register the generator and resolve it from the container:

```csharp
using CompactCodes;
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddCompactCodes();

using var provider = services.BuildServiceProvider();
var generator = provider.GetRequiredService<ICompactCodeGenerator>();
var code = generator.Generate();
```

`AddCompactCodes` validates its options immediately and registers a thread-safe singleton. If called more than once for the same service collection, the first registration wins.

## Core concepts

- **Alphabet:** The unique set of characters from which each symbol is chosen.
- **MinimumLength:** The preferred length generated by the current strategy.
- **MaximumLength:** A validated upper bound for future strategies; the current generator always uses `MinimumLength`.
- **DistributedRandom:** The default strategy uses cryptographic randomness to select each character uniformly.
- **Case-sensitive values:** Uppercase and lowercase characters are distinct and must remain distinct in storage and lookup.

## Configuration

`CompactCodeOptions` has these defaults:

| Option | Default | Allowed values |
| --- | --- | --- |
| `Alphabet` | `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz` (Base62) | Unique, non-empty RFC 3986 unreserved ASCII characters: letters, digits, `-`, `.`, `_`, `~` |
| `MinimumLength` | `10` | From `8` through `64`, inclusive |
| `MaximumLength` | `16` | At least `MinimumLength` and no greater than `64` |

The alphabet and `MinimumLength` must provide at least 40 bits of nominal code-space entropy. The default Base62 alphabet at length 10 provides about 59.5 bits. Invalid alphabets, lengths, and low-entropy combinations are rejected when the generator is constructed or registered.

Example custom configuration:

```csharp
services.AddCompactCodes(options =>
{
    options.Alphabet = "ABCDEFGHJKLMNPQRSTUVWXYZ23456789";
    options.MinimumLength = 12;
    options.MaximumLength = 16;
});
```

## Usage

Create a generated code for an invitation or campaign record:

```csharp
var code = generator.Generate();
```

For a custom alphabet, configure `AddCompactCodes` as shown above. The runnable example is [samples/CompactCodes.Sample/Program.cs](samples/CompactCodes.Sample/Program.cs).

## Safety and limitations

CompactCodes does **not** guarantee global uniqueness. Random codes occupy a finite space, so collisions become more likely as the stored population grows. Approximate birthday-collision probabilities for Base62 are:

| Codes generated | 8 characters | 10 characters | 12 characters |
| ---: | ---: | ---: | ---: |
| 1 million | ~0.229% | ~0.0000596% | ~0.0000000155% |
| 100 million | ~100% | ~0.594% | ~0.000155% |
| 1 billion | ~100% | ~44.9% | ~0.0155% |

When uniqueness matters, store the code under a database `UNIQUE` constraint and retry generation after a uniqueness conflict. This persistence and retry logic belongs to the consuming application; the sample does not connect to a database.

Use a case-sensitive database collation or comparison when the alphabet contains both letter cases. Otherwise, storage may treat distinct generated values (for example, `AbC123` and `abc123`) as equal.

The generator uses a cryptographic random source, but an unpredictable code is **not** an authentication or authorization mechanism. Do not grant sensitive access based only on possession of a generated code. Enforce authorization in the consuming system and use a dedicated threat model and entropy policy for capability tokens.

## Sample app

The console sample is in [samples/CompactCodes.Sample](samples/CompactCodes.Sample). It requires the .NET 10 SDK to build the full multi-target solution; the sample itself targets .NET 8.

Run it from the repository root:

```powershell
dotnet run --project samples\CompactCodes.Sample\CompactCodes.Sample.csproj --configuration Release
```

The generated code values vary on each run. Output has this shape:

```text
Default code: <10 Base62 characters>
Custom-alphabet code: <12 characters from the configured alphabet>
For uniqueness, enforce a database UNIQUE constraint and retry on collision.
```

## Testing & compatibility

The library and test project target .NET 8 and .NET 10. From the repository root, run:

```powershell
dotnet test CompactCodes.sln --configuration Release
```

This builds and tests both target frameworks. The sample can be run using the command in [Sample app](#sample-app).

The statistical test campaign reports duplicate observations from 100,000 generated 10-character values over a 16-character alphabet. It allows up to five observed duplicate values; from the expected 0.004547 colliding pairs, Markov's inequality bounds the probability of exceeding that limit to less than 0.1%. A nonzero collision count is not itself a failure.

Run the local benchmark campaign from the repository root:

```powershell
dotnet run --project tests\CompactCodes.Benchmarks\CompactCodes.Benchmarks.csproj --configuration Release
```

It measures serial codes/second and managed allocations/code, plus parallel codes/second, for lengths 8, 10, 12, 16, and 32 using Base62 and a smaller valid Base32 alphabet. The recorded local results and limitations are in [the benchmark report](tests/CompactCodes.Benchmarks/BENCHMARK_REPORT.md). These measurements are machine-specific observations, not a cryptographic certification.
